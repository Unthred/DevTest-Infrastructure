If it refuses with a named commit, file and hunk (missing or altered), restore that change in the commit it belongs to, run the checks again, and run rebase-push once more; never amend, squash, reword or reorder commits to fix it. If main removed the change on purpose, or the push is refused a second time, do not push by any other means: run rebase-stop with the reason. If it reports pushed:false because the branch moved during the job, stop and say so, repeating the message field of its output. A failure caused by the PR's own growth (the size ratchet, a test the PR's own change breaks) is out of scope for a rebase: run rebase-stop at once and do not fix it.
