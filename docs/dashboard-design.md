# Dashboard v2 design system (issue #54)

Source of truth: `supervisor/dashui/style.css` (tokens at the top). Tests read the tokens and check contrast.

- **Severity** (one scale everywhere): Action needed (red), Warning (amber), Info (blue), OK (green). Every badge carries an icon and a label, never colour alone. Mapping lives in `supervisor/dashui/logic.mjs` (`severityOf`).
- **Colour tokens**: light and dark sets (`:root`, `:root[data-theme=dark]`, and `prefers-color-scheme` when no choice is saved). Severity text on its background and body text meet 4.5:1 (7:1 for body); series colours meet 3:1 against the surface. Claude and Codex have one colour each (`--claude`, `--codex`), used in every chart and tag.
- **Type scale** 12/13/15/18/24/28 px; **spacing** 4/8/12/16/24 px; **radius** 10 px (6 px small); two elevations.
- **Icons**: 24x24 stroke icons drawn for this project, inlined as an SVG sprite. No third-party icon set or UI library is vendored, so nothing needs a digest or licence entry.
- **Components**: copy buttons (`data-copy`, hidden until the script runs; "Copied" confirmation), health cards (`.card.health.hc-<severity>`: a coloured top border plus a labelled badge), status badges, KPI tiles with sparklines, cards (drag handle, move earlier/later, expand, resize), designed empty states, skeleton class, sortable tables with footers and pagination.
- **Motion**: subtle transitions only; `prefers-reduced-motion` turns them off.
- **Breakpoints**: phone < 640 (bottom tab bar, tables become tap-to-expand cards, 44 px targets, reorder only), tablet 640-1099, desktop >= 1100 (Overview fits one screen). Layout is saved per breakpoint in `localStorage` (convenience only).

## Pages
`/` Overview, `/agents`, `/agents/<name>`, `/work`, `/work/pr/<n>`, `/work/issue/<n>`, `/activity`, `/usage`, `/reviews`, `/supervisor`, `/supervisor/ticks`, `/supervisor/upgrades` (issue #72, see [dashboard.md](dashboard.md)), `/system`. Table state (`<id>.sort|dir|q|page|size`) and chart range (`range=24h|7d|30d`) are in the URL, so every view is bookmarkable and works without script.

## Security and constraints
Read-only (GET/HEAD), no GitHub or model call on page load, no CDN. CSP: `script-src 'self'` serves only `/static/app.js` and `/static/logic.mjs` (fixed whitelist); no inline script. The script sends nothing anywhere; copy buttons only write to the local clipboard.

## Polish (issue #58)
- **Layout editor (replaces per-edge resize and header-handle dragging):** on desktop and tablet each page with cards has one **Edit layout** control. Each card then has a saved position and size in grid cells (`supervisor/dashui/grid.mjs`): 24 columns on desktop, 12 on tablet (twice as fine as the old 12 and 6) and rows of 12 px with a 12 px gap. The only limits are a 3 column by 4 row minimum (a usable header) and 400 rows. Empty space is allowed. In layout mode a card is dragged from anywhere and resized from any edge or corner with a live landing preview; other cards move down only when they must and by the least amount; arrow keys move a focused card and Shift+arrows resize it. Done leaves the mode; outside it nothing moves. **Undo/Redo**, **Reset to default**, **Tidy up** (closes gaps only when asked) and the **card picker** (issue #927: the cards available for the page; **Add** puts one on the page and **Remove** takes it off, so a card not chosen is simply not there; the approvals panel, Needs you, the breaker and any `data-pin` card cannot be removed), and **Group** / **Ungroup** (drag a selection box on empty space, or Shift+click, to select cards, then Group them: the group moves, and closes gaps in Tidy up, as one block, stays a group until ungrouped, and is saved with the layout as `groups`). The layout bar's controls sit on the right are in the layout bar. Content adapts: a card scrolls what does not fit, charts scale to the card, KPI tiles reflow. Saved per page and breakpoint as `{ v: 2, pos, hidden, groups, collapsed }` in `localStorage`; an old order/span/height layout keeps applying until the viewer edits, then converts from the cards as drawn; a bad value falls back to the default flow. The periodic refresh is paused while layout mode is on. A phone keeps its order-only layout (earlier/later buttons). Library choice: no grid library (GridStack was considered); the collision rules, undo and conversion are small, pure and unit-tested, and the CSS grid does the placement, so nothing new is vendored.
- **Sizing:** no fixed card heights or inner scrolls at default size. Cards in a row stretch to equal height (Overview); list pages (`.cards.fit`) let each card fit its content. KPI tiles share one shape. Charts take the full card width.
- **Back:** every page except Overview has a breadcrumb (Overview › Work › PR #41) and a Back control. Back uses browser history when the previous page was this dashboard, else links to the parent. Filters, sort and page are in the URL; scroll position is kept per address in `sessionStorage` and restored on back/forward and after the periodic refresh.
- **Scrollbars:** true overlay. Once the script runs, native bars are hidden (`scrollbar-width:none`; wheel, keyboard and touch scrolling stay native) and a thin themed thumb is drawn fixed over the scroller's edge, so it takes no layout space. It shows on pointer-over or while scrolling, is draggable, and looks the same in Chrome, Edge and Firefox. Without script the native bars remain.
- **App bar (issue #924):** brand, page title, health, agents, last tick, next, page data, then a sticky toggle and the theme button, all right-aligned. Version, Data and Team loop are not in the bar; they are on the System page. Back and the breadcrumbs sit in a strip just below the bar. The sticky toggle (`dash.sticky`) pins the bar, and the breadcrumb strip under it, while scrolling.
- **Menu width:** a left or right menu has a set width (default 13rem). A draggable divider on its inner edge (also keyboard: Left/Right arrows, Home to reset) sets it between 140 and 480 px; the width is remembered (`dash.navw`) and applied by `static/early.js` before first paint.
- **Dockable navigation:** top, bottom, left or right, by dragging the grip at the nav's edge or the Nav buttons in the status bar; saved per breakpoint (`dash.dock.<bp>`). Left and right show a vertical rail with a collapse toggle (icons only when collapsed). A phone always keeps the bottom tab bar. `static/early.js` applies the saved dock before first paint.
- **Version badge:** installed is the commit the `current` link points at (so manual upgrades show at once); main comes from the upgrade records, and no drift is claimed if the link moved after the newest record. A server loaded from an older `versions/<sha>` than the link shows "running X, installed Y, restart pending" in amber (the running commit is also `version.running` in the status data). The upgrader restarts the server after a verified install and after a rollback, checks that it answers `/api/view.json`, and a failed restart raises one alert while the old process keeps serving.

## Lists (Overview)
Every list on the Overview is one shared component: `dli()` builds a row and `dlist()` builds the list (`supervisor/dashrender.mjs`), with the pure sort, search and footer logic in `supervisor/dashui/lists.mjs` and the browser side in `lists-ui.mjs`. A test fails if a plain `panel-list`, `watch-list` or `since-list` appears on the Overview outside it. The Work and System pages can adopt it by rendering their rows through `dlist()`; they are not converted yet.
- **Height**: a maximum (`--dl-max`, viewport-based, smaller on a phone), so the page does not grow with the row count and a short list is only as tall as its rows. A resized card or an expanded card raises it.
- **Search and sort** need the script (without it the bar is hidden and the list still shows and scrolls). The search box appears from 6 rows. The sort controls name the current sort and direction in words.
- **State** (search text, sort, scroll inside the list, open details) is kept per page and list in `sessionStorage` and re-applied to any list that appears, including one swapped in by an in-place refresh.
- Browser check: `node tests/lists-browser.mjs <dir>` (Tower, pinned Chromium; `LISTS_SRC=<checkout>` measures another checkout's page heights).

## Page purposes (issue #935, proposal awaiting homeowner agreement)
Status: **proposal**. No content has moved yet. The moves in "Moves to make" are done in follow-up work after the homeowner agrees this section in an issue #935 comment. This section describes the pages as they are today and what each should become.

**Rule.** The Overview is a summary only. Every number or item on it is a link to the page where all the relevant detail can be inspected. A fact has one home page; any other page shows at most a count or one line that links to the home.

| Page | The one question it answers | Holds | Overview items drill down here |
|---|---|---|---|
| Overview `/` | Is anything wrong, and is work moving? | Health strip, Now, Next, Needs you, Later, Warnings, Watching, Since you were last here, KPI tiles, two charts. Counts and one-line items only. | each item links to its detail page |
| Agents `/agents` | Who can work right now, and what are they doing? | One card per agent: state, provider, current job, allowance/budget, queue length. `/agents/<name>` has current job, queue and job history. | Jobs running, Agents available, Now |
| Work `/work` | What work exists, and where is each item in its life? | Queues (by role, see below), Issues, Pull requests, Excluded issues. `/work/pr/<n>`, `/work/issue/<n>` hold timelines, verdict history, dependencies. | Open pull requests, Queued items, Next, Needs you, Later |
| Activity `/activity` | What happened, and when? | Jobs-per-day chart, event timeline, per-issue activity. | Jobs per day |
| Usage and cost `/usage` | What is the work costing, against the allowance? | Allowance over time, tokens per merged PR / job / model, failed attempts. | Allowance used, Tokens recorded |
| Reviews `/reviews` | Is review catching things, and how fast does work merge? | Verdicts per agent, issue start to merge, verdict history. | Reviews recorded |
| Supervisor `/supervisor` | Is the dispatcher itself healthy? | Health cards (tick, errors, drift, test slots, leases summary), Recent ticks, Leases table. `/supervisor/ticks`, `/supervisor/upgrades`. | the health strip |
| Diagnostics `/diagnostics` | Where does time go between steps? | Tick gaps, job-to-job turnaround, review-to-verdict, idle time by cause, passes by trigger, recorder load. | none (opened from Supervisor and System) |
| System `/system` | What is installed and how fresh is its data? | Dispatcher facts (repository, Team loop state, data freshness, page built), Version, All attention items, links to processes and UI review evidence. | Warnings, Data age |

### Questions settled
- **Queues: by role, not by agent.** The system is agent-agnostic, so a queue per agent name ("claude", "codex") ties the page to today's staffing. Work shows queues by role: implementer, reviewer, rebaser (and fixer if the dispatcher keeps it as its own role). Each row says which agent holds it. The Agents page stops showing a per-agent queue list; an agent card shows only "N queued for this agent" linking to `/agents/<name>`, where that agent's queue stays. Work is the one place to see a whole queue. Needs from the dispatcher view: queue items tagged with a role (today they are keyed by agent name in `view.queues`), so this is a data-shape change plus a render change.
- **Supervisor Leases.** Two cards show the same data: the Leases health card (count and "needs recovery") and the Leases table. Keep one: the health card becomes a one-line summary ("3 held, 0 need recovery") that scrolls to the table, and the table card carries an explanation: "A lease is the lock a running job holds on its slot, stored under `leases/*`. It is released when the job ends. A stale lease means the job is gone but the lock was not released and needs recovery." The table's empty state keeps the same wording.
- **App bar: Data and Team loop.** Already out of the bar since #924. Data (age of the cached GitHub data) and Team loop (whether the dispatcher is allowed to start team work, from `docs/team-loop.md`) are system facts for an operator, not things to scan on every page. They live on System; Overview keeps only the Data age tile, linking to System. Homeowner to confirm they do not want either back in the bar.
- **Version** is on System only (done in #924). Supervisor's Version health card is the upgrade history and stays on Supervisor, because it answers "did the self-upgrade work", not "what is installed"; it links to `/supervisor/upgrades` and shows no commit already shown on System. Homeowner to confirm.
